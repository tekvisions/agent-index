Choose an AI agent framework by execution needs

Start with the work your agent must complete and the state it must preserve. This catalog spans SDKs, orchestrators, multi-agent systems and supporting components; its GitHub momentum order is a discovery signal rather than a framework-quality verdict.

Guide sources reviewed 2026-11-03. Catalog snapshot: 2026-11-02T20:24:34.123043+00:00. Source review does not mean runtime testing.

Build one typed tool-using agent

Check tool schemas, output validation, supported model providers and a complete example for your language. Run a small task with a known expected answer before introducing more agents.

Current catalog categories: Agent SDKs; Agent Frameworks.

Resume a workflow and review its actions

Inspect checkpoint storage, retry behavior, state migration and human approval points. Verify what survives a failed tool call and how a run is resumed in the version you will deploy.

Current catalog categories: Orchestration; Memory & State.

Coordinate agents or execute actions

Define handoffs, termination conditions, tool permissions and a time/cost budget. Evaluate the whole task, including failures and unwanted actions, rather than only the final response.

Current catalog categories: Multi-Agent; Autonomous Agents; Tools & Browser.

Evidence to check before choosing

  • Record the package version, model/provider and deployment target used in your test.
  • Keep a task set with expected outputs and tool-call traces; compare correctness, recovery behavior, latency and cost under the same conditions.
  • Check both framework and plugin documentation; capabilities overlap across these catalog categories.

Source-checked starting points

  • langchain-ai/langgraph — Its primary README describes orchestration for stateful workflows, including persistence and human intervention. Verify the APIs and storage behavior for your selected version. Primary source.
  • pydantic/pydantic-ai — Its primary README describes a typed Python agent SDK and validated outputs. Verify the tool/output contracts with a task-specific example. Primary source.

What remains unknown

No comparative task-success, security, latency or cost benchmark is verified by this directory. A category does not imply that other frameworks lack the same feature.
